# MacClean 설계 문서

256GB MacBook Air 를 위한 저장 공간 정리 도구.

---

## 1. 문제 정의

### 1-1. "시스템 데이터"는 폴더가 아니다

macOS 의 저장 공간 화면에 나오는 "시스템 데이터"는 실제로 존재하는 폴더가 아니다.
**macOS 가 앱·사진·영화·음악·문서 중 어디로도 분류하지 못한 모든 것의 합계**다.
그래서 "시스템 데이터를 지운다"는 건 애초에 불가능하고, 그 안에 뭐가 들어있는지를
쪼개서 봐야만 손댈 수 있다. 이 도구의 첫 번째 화면이 "진단"인 이유다.

실제 구성은 대체로 이렇다.

| 구성 요소 | 전형적 크기 | 이 도구의 대응 |
|---|---|---|
| Time Machine 로컬 스냅샷 | 5–60GB | 진단만 (안내) |
| Xcode DerivedData | 5–40GB | 안전 정리 |
| iOS 시뮬레이터 런타임/기기 | 10–50GB | 안전/안내 |
| iPhone·iPad 로컬 백업 | 10–50GB | 확인 후 휴지통 |
| 앱 캐시 (`~/Library/Caches`) | 2–20GB | 안전 정리 |
| 개발 도구 캐시 (npm/pip/brew…) | 1–15GB | 안전 정리 |
| 로그·크래시 리포트 | 0.1–2GB | 안전 정리 |
| 슬립이미지·스왑 | 2–10GB | 손대지 않음 (시스템 관리) |

### 1-2. 가장 중요한 사실: 스냅샷이 삭제를 무효화한다

Time Machine 은 외장 디스크가 없어도 **내장 디스크에 로컬 스냅샷**을 만든다.
스냅샷은 그 시점의 파일 블록을 붙잡고 있다. 따라서:

> 스냅샷이 남아 있는 동안에는, 파일을 지워도 여유 공간이 늘지 않는다.
> 지운 만큼이 그대로 "시스템 데이터"로 옮겨 갈 뿐이다.

이걸 모르면 "정리 앱을 돌렸는데 용량이 그대로"라는 경험을 하게 된다.
그래서 이 도구는 **정리 결과를 약속하기 전에 스냅샷 상황부터 보여준다.**

스냅샷 삭제는 `sudo` 가 필요하다. 이 앱은 관리자 권한을 절대 요구하지 않으므로
진단 결과와 명령어만 제공하고, 실행은 사용자가 직접 한다.

### 1-3. 이 도구가 풀지 않는 문제

- 중복 파일 찾기 (v1 범위 밖)
- 앱 삭제 / 언인스톨러
- 시스템 파일 최적화, 메모리 정리 같은 "튜닝"
- 관리자 권한이 필요한 모든 작업

## 2. 안전 정책

> 설계 목표: **어떤 버그가 있어도 사용자 데이터는 사라지지 않는다.**
> 못 지우는 실패는 허용한다. 잘못 지우는 실패는 허용하지 않는다.

### 2-1. 다섯 가지 원칙

1. **허용 목록만 (Allowlist-only)**
   `RuleCatalog` 에 명시된 경로만 후보가 된다.
   "N일 지난 파일을 찾아 지운다" 같은 휴리스틱은 존재하지 않는다.

2. **되돌릴 수 있게 (Reversible by default)**
   기본 처리 방식은 **휴지통 이동**이다. 완전 삭제는 "휴지통 비우기" 하나뿐이고,
   그건 본질적으로 영구인 작업이라 예외다. 휴지통 이동이 실패하면
   **완전 삭제로 대체하지 않고 그냥 포기한다.**

3. **권한 상승 없음 (No sudo, ever)**
   관리자 권한을 요구하지 않는다. 권한이 필요한 작업은 안내만 한다.
   앱이 실행할 수 있는 외부 명령은 `ShellRunner.allowedExecutables` 에 등록된 것뿐이고,
   셸(`/bin/sh -c`)을 거치지 않으므로 인자 주입이 성립하지 않는다.

4. **두 번 검사 (Verify twice)**
   스캔할 때 한 번, **실행 직전에 한 번 더** 같은 관문을 통과시킨다.
   그 사이에 파일이 바뀌었으면 건너뛴다.

5. **전부 기록 (Audit everything)**
   무엇을, 왜, 얼마나, 어디로 옮겼는지 JSONL 로 남긴다.

### 2-2. 3단 위험 등급

| 등급 | 기본 선택 | 처리 방식 | 예시 |
|---|---|---|---|
| **안전** | ✅ | 휴지통 | DerivedData, npm 캐시, 앱 캐시, 로그 |
| **확인 필요** | ❌ | 휴지통 | iPhone 백업, iOS DeviceSupport, node_modules, pnpm store |
| **안내 전용** | 선택 불가 | **손대지 않음** | 로컬 스냅샷, 대용량 파일, 시뮬레이터 런타임 |

"안내 전용"은 체크박스 자체가 없다. 실행기도 이 등급을 만나면 무조건 건너뛴다.

### 2-3. 관문 (PathGuard) — 7개 게이트

모든 후보 경로는 예외 없이 이 순서를 통과해야 한다.

| 게이트 | 검사 내용 |
|---|---|
| **G1** | 절대 파일 경로인가, `..` 이 없는가, 볼륨 루트가 아닌가 |
| **G2** | 존재하는가, 심볼릭 링크가 아닌가, 링크를 푼 경로도 안전한가 |
| **G3** | 보호 경로 목록에 걸리는가 (**규칙이 덮어쓸 수 없음**) |
| **G4** | 규칙이 허용한 루트 안인가, 홈 자신이나 그 상위가 아닌가 |
| **G5** | 규칙이 요구하는 최소 깊이를 넘는가 |
| **G6** | 현재 사용자 소유인가, 같은 볼륨인가, SIP·잠금 플래그가 없는가 |
| **G7** | 상위 디렉터리에 쓰기 권한이 있는가 |

### 2-4. 보호 경로 (G3)

`ProtectedPaths` 에 하드코딩되어 있고, **규칙이 덮어쓸 수 없다.**

- **시스템**: `/System`, `/usr/bin`, `/Library/Apple`, `/Applications`, `/private/var/db`, `/Volumes` …
- **사용자 데이터**: `~/Documents`, `~/Desktop`, `~/Pictures`, `~/Movies`, `~/Music` …
- **클라우드 동기화**: `~/Library/Mobile Documents` (iCloud Drive), `~/Library/CloudStorage`, `~/Dropbox` …
  — 여기서 지우면 **클라우드에서도 지워진다.**
- **자격 증명**: `~/Library/Keychains`, `~/.ssh`, `~/.aws`, `~/.gnupg`, 프로비저닝 프로파일
- **이름 기반**: 경로 어디에든 `.git`, `.ssh` 가 있으면 차단
- **번들**: `.photoslibrary`, `.fcpbundle`, `.app`, `.logicx` 내부는 통째로 차단

#### 예외는 단 한 가지 방식으로만

iPhone 백업(`~/Library/Application Support/MobileSync/Backup`)은 기본 보호 대상이지만
사용자가 명시적으로 골라 지울 수 있어야 한다. 이런 경우를 위해
`RuleConstraints.exemptProtectedPrefix` 가 있다.

중요한 건 이 예외의 **범위가 좁다**는 점이다.

- 접두사 **하나**만 열린다
- **G3 의 경로 접두사 판정에만** 적용된다
- 이름 기반 차단(`.git`)·번들 차단은 열리지 않는다
- **G1·G2·G4~G7 은 그대로 전부 적용된다**

### 2-5. 클라우드 파일 함정

iCloud "Mac 저장 공간 최적화"가 켜져 있으면 클라우드에만 있는 파일이 로컬에
0바이트짜리 자리표시자로 남는다. 논리 크기로 계산하면 실제보다 훨씬 크게 나온다.
APFS 파일 복제(clone)와 스파스 파일도 같은 문제를 만든다.

그래서 크기 계산은 **논리 크기가 아니라 할당 크기(`totalFileAllocatedSize`)** 를 쓴다.
"이만큼 확보됩니다"라는 숫자가 실제와 맞아야 하기 때문이다.

## 3. 구조

```
MacCleanCore (순수 Foundation · UI 의존 없음)
├─ Models/       Finding, RiskLevel, RemovalMode, FindingCategory
├─ Safety/       ProtectedPaths, PathGuard          ← 마지막 방어선
├─ Rules/        CleanupRule, RuleCatalog           ← "무엇을 지울지"의 전부
├─ Scanning/     Scanner 규약 + 스캐너들 + ScanCoordinator
├─ Execution/    CleanupExecutor, AuditLog
└─ Support/      DiskUsage, ShellRunner, VolumeProbe, UserPaths

MacCleanApp (SwiftUI)     — 코어를 화면에 붙인다
maccleanctl (CLI)         — 코어를 GUI 없이 검증한다
```

의존 방향은 한 방향이다. 코어는 앱을 모른다.
"지금 실행 중인 앱" 같은 AppKit 정보는 `ScanContext` 로 주입받는다.

### 3-1. 규칙은 코드가 아니라 데이터

`CleanupRule` 은 `Codable` 구조체다. 이렇게 한 이유:

- 전체 규칙을 한 화면에서 검토할 수 있다 (`maccleanctl rules`)
- 테스트가 규칙을 순회하며 불변식을 검사할 수 있다
- 규칙이 아무리 잘못 쓰여도 `PathGuard` 를 우회할 방법이 없다

### 3-2. 실행 흐름

```
[검사]  ScanCoordinator
          → 각 Scanner 가 후보 생성 (각 후보는 PathGuard 통과)
          → 겹치는 후보 정리 (조상 경로는 버림)
          → ScanReport

[검토]  사용자가 항목별로 확인
          → "안전" 등급만 기본 체크
          → 각 항목마다 "지우면 어떻게 되는지" 표시

[확인]  확인 시트
          → 몇 건이 어디로 가는지
          → 되돌릴 수 없는 항목이 몇 건인지
          → 휴지통을 비워야 실제 용량이 는다는 안내

[실행]  CleanupExecutor  (항목마다)
          → 안내 전용인가?          → 건너뜀
          → 제약 정보가 있는가?     → 없으면 건너뜀
          → PathGuard 재통과        → 실패 시 건너뜀
          → 스캔 이후 변경됐는가?   → 변경됐으면 건너뜀
          → 휴지통 이동 (실패해도 완전 삭제로 대체하지 않음)
          → 감사 로그 기록
```

`Finding` 이 자신을 만든 `RuleConstraints` 를 들고 다닌다.
스캔할 때 쓴 제약과 실행 직전에 쓰는 제약이 **반드시 같도록** 보장하기 위해서다.

### 3-3. 겹치는 후보 정리

규칙이 겹치는 건 정상이다. `~/Library/Caches` 를 훑는 일반 규칙과
`~/Library/Caches/Homebrew` 전용 규칙은 같은 경로를 두 번 내놓는다.
그대로 두면 용량이 이중 계산되고, 부모를 지운 뒤 자식을 지우려다 실패한다.

정책: **더 구체적인(깊은) 후보를 남기고 조상은 버린다.**
덜 지우는 쪽으로 기우는 선택이고, 항목 설명도 더 정확해진다.

## 4. 권한

### 4-1. 샌드박스를 쓰지 않는다

샌드박스 안에서는 `~/Library` 를 읽을 수 없어서 이 앱이 하려는 일 자체가 불가능하다.
따라서 App Store 배포는 불가능하고, 개인용 도구로만 쓴다.

### 4-2. 전체 디스크 접근

다음 항목은 이 권한 없이는 보이지 않는다. (권한이 없으면 조용히 빈 폴더로 보인다)

- iPhone·iPad 백업
- 메일 첨부 임시본
- 샌드박스 앱 캐시 (`~/Library/Containers/*/Data/Library/Caches`)

`FullDiskAccessProbe` 가 미리 찔러보고, 없으면 배너로 알린 뒤 설정 화면을 열어준다.

## 5. 테스트 전략

가장 중요한 테스트는 "지워지는가"가 아니라 **"안 지워지는가"** 다.

- `PathGuardTests` — 보호 경로·심볼릭 링크·깊이·예외 범위
- `RuleCatalogTests` — 규칙 불변식 (보호 경로를 겨냥하지 않는가, 완전 삭제가 휴지통뿐인가 등)
- `ToolCommandTests` — 허용 목록 밖의 명령이 거부되는가
- `DeduplicationTests` — 겹치는 후보 정리 규칙

```bash
swift test
```
